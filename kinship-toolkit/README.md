# kinship-toolkit

Невеликий набір інструментів без залежностей (лише стандартна бібліотека Python 3.10+) для генеалогічного
дослідження за методикою навички `ex-ussr-kinship-research`: реєстри в CSV → перевірка дерева → GEDCOM → звіт.
Створений, щоб дослідження було **повторюваним і дешевим за токенами** — і щоб друзі могли запустити його самі.

## Що вміє

| Модуль | Призначення |
|---|---|
| `kin/names.py` | «скелет» прізвищ (кирилиця ↔ польська/німецька/латинська транслітерація, -ів/-ów/-iv/-ев → `V`, -ський/-ski → `SK`), схожість, відповідність імен (Іван ↔ Jan), `query_variants` — усі правдоподібні написання для індексів із точним збігом (так знаходиться Mychaszkow, коли шукали Michaśków) |
| `kin/entity.py` | зіставлення згадок про людей між парафіями/мовами: зважена оцінка + **жорсткі заборони** (вік, роки, імена батьків), кластери з поясненням |
| `kin/graph.py` | перевірка дерева: цикли, вік батьків, народження після смерті батька, тезки, статус «підтверджено» без двох незалежних груп |
| `kin/gedcom.py` | експорт у GEDCOM 5.5.1 (живі приховані), незалежний валідатор, перевірка через `python-gedcom` |
| `kin/fetch.py` | ввічливий HTTP-клієнт: кеш, пауза на хост, повтори, зупинка при 403/429 |
| `kin/ia_fts.py` | повнотекстовий пошук Internet Archive (газети, шематизми, довідники): спершу сніпети, OCR лише відібраного |
| `kin/avr.py` | публічний каталог avr.org.ua: один раз завантажити, далі шукати локально |
| `browser/*.js` | Playwright-скрипти для Geneteka та пошуку в каталозі FamilySearch під **вашим** акаунтом |

## Швидкий старт

```bash
python -m unittest discover -s tests          # 15 тестів, мережі не потребують
python -m kin validate  ./case                # цикли, вік, тезки, сила доказів
python -m kin gedcom    ./case ./tree.ged     # експорт + перевірка структури
python -m kin ia  "Kowalski Zalesie" --key "Kowalsk\w+" -n 10
python -m kin avr "Заліськ|Zalesie"
```

`./case` — каталог зі `person-register.csv` та `relationship-register.csv` у форматі навички.
**Не кладіть каталог справи в git**: там живі люди. `.gitignore` це підстраховує, але перевіряйте самі.

## Чого цей набір свідомо НЕ робить

- **Не ротує проксі, не обходить rate-limit, CAPTCHA, 403/429 і закриті API.** При відмові `Fetcher` зупиняє
  хост (`HostBlocked`), а ви фіксуєте блокування в `search-log` і шукаєте законну альтернативу (дзеркало, інший архів,
  запит до архіву, ручний перегляд власним акаунтом). Обхід захисту — це порушення правил сайтів і не потрібен для результату.
- **Не завантажує масово зображення FamilySearch.** Умови сервісу вимагають письмового дозволу; скрипт лише знаходить шифри.
- **Не доводить родинність.** Усі виходи — кандидати з поясненням; рішення про злиття приймає людина за документами.

## Про «оптимальність» зіставлення

Алгоритм у `entity.py` — не «математично оптимальний», а *прозорий*: зважена сума схожостей
(прізвище 0.40, ім'я 0.20, рік 0.20, місце 0.10, батьки 0.10) **після** жорстких заборон, що ловлять типові хибні злиття
(12-річний «власник» 1899 р.; мати, народжена пізніше за сина). Кластеризація — single-link у порядку спадання оцінки з
повторною перевіркою заборон при кожному злитті. Поріг (0.75 за замовчуванням) і ваги — параметри; підбирайте їх на
власних розмічених парах. Фонетика (`names.py`) — лише для відбору кандидатів.
